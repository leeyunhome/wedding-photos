## Architecture (intended)

**Next.js 15 App Router** (TypeScript, Tailwind) deployed to **Cloudflare Pages**; all photos stored in **Cloudflare R2** (egress is free).

### Data flow — single entry point

`lib/storage.ts` is the **only** data source for page components. It reads `NEXT_PUBLIC_R2_PUBLIC_URL`: if set, it fetches `manifest.json` from R2 (with `next: { revalidate: 300 }`); if unset, it returns mock data so the app runs locally without R2 credentials. Never fetch R2 or read the manifest directly from a page — go through `getPhotos()` / `getPhoto(id)`.

### R2 bucket layout

```
wedding-photos (R2 bucket)
├── manifest.json          # full photo metadata list (the data source)
├── photos/{uuid}.jpg      # full-size images
└── thumbnails/{uuid}.jpg  # low-weight thumbnails
```

`manifest.json` is **generated by the upload script**, not hand-edited in R2. To change titles / categories / tags, edit the local `manifest.json` (or the script's metadata) and re-run the upload script — it regenerates and re-uploads the manifest.

### Source photo layout (what's in `images/` now)

All under `images/260328이윤호.진수빈/` (~1300 JPGs total). Subfolders are meaningful groupings to preserve as categories/sets when building the manifest:
- root (`260328이윤호.진수빈/`) — main set (~884)
- `3.28 이윤호 진수빈11` — additional set (~230)
- `기념촬영` — commemorative / group shots (~121)
- `신부대기실` — bride's waiting room (~86)
- `진수빈13x10-54p화보집` — printed album selects (~54)
- `(진수빈)신랑댁12p`, `(진수빈)신부댁12p` — groom's/bride's family sets (~12 each)

Note filenames use `.JPG` (uppercase) and the tree contains macOS/Windows artifacts (`.DS_Store`, `Thumbs.db`) — exclude these when uploading.

### Environment variables

Create `.env.local` (gitignored, never commit) and a value-less `.env.example` (committed). R2 credentials (`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`) stay server-side; only `NEXT_PUBLIC_`-prefixed vars (e.g. `NEXT_PUBLIC_R2_PUBLIC_URL`) reach the client.

### Deployment

Cloudflare Pages, auto-deploy on push to the connected GitHub branch. `wrangler.toml` must set the `nodejs_compat` compatibility flag (also enable it in the Pages dashboard runtime settings). Any API routes must declare `export const runtime = "edge"`. Pages build command: `npx @cloudflare/next-on-pages@1`, output dir `.vercel/output/static`.
